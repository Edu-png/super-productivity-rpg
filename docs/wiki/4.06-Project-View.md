# Project View

A **project** is the primary way to organize tasks in Super Productivity. Every task belongs to exactly one project, making projects the main organizational structure for your work.

## What Projects Are

Projects are self-contained workspaces. Each project has:

- **Task lists** — Active tasks and an optional backlog
- **Notes** — Project-specific notes
- **Theme settings** — Custom colors and appearance
- **Integration settings** — Connections to external issue trackers (like Jira or GitHub)

When you switch to a project view, you see only the tasks that belong to that project, along with the project's notes and settings.

## Projects Vs Tags

Projects and tags serve different organizational purposes:

| Aspect                    | Projects                                                         | Tags                                                |
| ------------------------- | ---------------------------------------------------------------- | --------------------------------------------------- |
| **Relationship to tasks** | Each task belongs to exactly **one** project (required)          | Each task can have **zero or more** tags (optional) |
| **Purpose**               | Primary organizational structure — every task has a home project | Secondary labels for cross-cutting categorization   |
| **Features**              | Backlog, notes, theme, integrations                              | Simple labels for filtering and grouping            |

A task must always belong to a project. Tags are optional labels you can add to tasks across different projects to create cross-cutting categories.

## Project Features

**Backlog**: Projects can have a separate backlog list for tasks you're not actively working on. You can move tasks between the active list and the backlog.

**Notes**: Each project can have its own notes, separate from task notes.

**Theme**: Projects can have custom colors and appearance settings to help you visually distinguish them.

**Integrations**: Projects can connect to external issue trackers (like Jira, GitHub, GitLab) to sync tasks and track work.

## Organizing Projects

Projects themselves are **flat** — there are no parent projects or subprojects. A project cannot contain other projects.

However, you can **organize projects into folders** in the navigation menu. Folders can be nested (folders within folders) to create a hierarchy for navigation, but this is purely for organization — it doesn't change how projects work or how tasks are stored.

You can move projects between folders without affecting the tasks or any other project data.

Use the folder-plus button beside **Projects** to create a macro folder such as
Work, Study, or Home. Drag existing projects into it, or use the folder's
three-dot menu to create a project directly inside that folder. The name field
opens focused, so type the folder name and press Enter. Folders can be expanded
and collapsed, and their ordering is persisted and synchronized.

Each folder receives a stable accent color for its icon, side marker, and subtle
background. Project colors remain independent inside the folder, so the folder
communicates the broader area while every project keeps its own identity.

## Hiding Projects

When a project is active but you do not want it in the sidebar project list, enable **Hide project from sidebar** in the project settings or use the Projects visibility menu in the sidebar.

Hiding a project changes navigation only. The project stays active, and its tasks can still appear in cross-project task views such as Today, Planner, Schedule, Boards, and Search. Project navigation helpers, including project short syntax, do not match hidden projects.

## How Tasks Belong to Projects

Every task has a project assignment. When you create a task, it's assigned to the current project (or the Inbox if you're in a tag context without a default project). You can change a task's project by:

- Dragging and dropping the task to another project in the navigation
- Editing the task and selecting a different project

When you view a project, you see all tasks that belong to it. When you view a tag, you see tasks from multiple projects that have that tag, and each task shows its project as a badge.

## Completing Projects

When you finish with a project, you **complete** it to retire it from your active workflow and celebrate the result. Right-click the project in the sidebar (or click the `⋮` button) and choose **Complete project**.

If the project still has **unfinished tasks**, you're asked what to do with them first: **Move to Inbox** (the default — they stay actionable), **Mark as done**, or **Cancel**. Before the project is completed, a final confirmation asks you to confirm the action.

On completion you get a full-screen **celebration** with a short summary — tasks done, time tracked, days worked, and how many days the project ran from its first worked day to completion (time-based stats are hidden when you don't track time).

A completed project becomes fully **dormant** — all its data is preserved, but it stops generating noise across the app. Specifically, it:

- Is removed from the sidebar project list and the main visibility checklist
- Has its tasks hidden from Today, Tags, Boards, Overdue, Deadline, and Scheduled views
- Has its repeating tasks suspended — no new instances are generated
- Has its reminders suppressed — no notifications fire for its tasks

**Finding and reopening** completed projects: click the eye icon in the Projects section header to open the visibility menu, then navigate to **Archived projects**, where completed projects appear with a trophy badge and their completion date. Use the **Reopen** action there to clear the completed state and bring the project back to the sidebar with all tasks, repeating configs, and reminders active again.

## Folder metrics

Project folders expose a **Metrics** entry in their context menu. The folder view
aggregates the task, estimate, tracked-time, and break metrics of every project
inside the folder, including projects nested in subfolders. Projects remain
independent; moving a project in or out of a folder changes the next aggregated
view without copying or modifying its tasks.

## RPG profile

The RPG profile can associate each project with a character attribute. Completed
tasks award XP based on their estimate (one XP per estimated minute, with a
five-XP minimum), and every ten XP unlocks one spendable coin. XP awards are
recorded per task, so toggling completion cannot award the same task twice.
Discipline is the average completion percentage across days that contain at
least one scheduled or completed top-level task; empty days are excluded.
Four original pixel-art character presets are bundled with the profile. Users can
switch classes at any time or keep using a custom uploaded avatar.

The character sheet also includes a five-axis radar chart, selectable classes and
subclasses with real XP, coin, quest, or attribute bonuses, equippable achievement
titles, and progress medals. Daily quests are generated from the current calendar
day (task completions, tracked focus time, and full-day completion). Each
date-and-quest pair can award its XP and coins only once.

All classes are available from character creation onward and use symbolic icons,
such as a book for the mage. Subclasses are progression rewards: the selector
shows locked paths and their required level, with advanced subclasses continuing
through level 100. Both the interface and profile service reject subclass
selections made before their unlock level.

Species are selected only while creating a character. Human, elf, dwarf, orc,
and fae are initially available; the chosen species is immutable afterward.

Creating a character opens a dedicated RPG editor instead of choosing from
preset portraits. It captures class, species, gender, body and face shape, skin
and eye colors, hairstyle and color, beard, and accessory. The character starts
with simple traveler clothing and a class-appropriate basic weapon already
equipped; later equipment changes come from inventory progression.

The editor, party list, character sheet, and inventory share the same reactive
`CharacterRenderer`. It composes transparent 64 by 64 PNG sprites from a
data-driven manifest, using a fixed layer order and nearest-neighbor rendering.
Body, ears, eyes, face, clothing, armor, split back/front hair, beard,
accessories, helmet, weapon, shield, and effects remain independent assets.
Changing species, gender, class, appearance, or equipped inventory items redraws
the preview immediately, while decoded sprites remain cached. Asset authoring,
alignment rules, and the placeholder replacement list are documented in
`docs/character-assets.md`.

The creator uses curated palettes instead of unrestricted color pickers and
offers expanded hair, facial hair, eyebrow, eye, nose, mouth, and marking
choices. Existing saved characters are migrated by merging the new appearance
defaults, so older profiles remain renderable.

Inventory and progression panels use a classic taskbar-RPG treatment: dark metal
and red-gold frames, recessed equipment slots, rarity borders, compact item
grids, and a full celestial talent map called **Constellations of Destiny**.

Every profile card uses the same red-and-gold title treatment. The constellation
map supports drag, smooth zoom, camera reset, animated star states, connected
paths, rarity-based node sizes, lore tooltips, and a live character-stat panel.
Stars are data-driven and can define position, prerequisite connections, cost,
maximum rank, required level, rarity, icon, and XP, gold, luck, or rare-drop
effects. One Star Point is earned per character level, and the service rejects
isolated, unaffordable, level-locked, and fully ranked purchases. Purchased
effects immediately feed the character's real XP and gold multipliers.
Discipline history includes a 14-day line chart as well as the detailed daily
rows. Existing Ring of Power records are enriched during profile migration so
older characters receive the pixel-art asset instead of retaining the former
generic icon.

Avatar uploads accept images as well as MP4 and WebM video loops. The profile
page uses its own original pixel-art dungeon background, leaving the rest of the
application theme unchanged.

In addition to daily quests, each character receives a monthly quest based on
completed calendar tasks. The initial inventory contains an equippable pixel-art
**Ring of Power**, which grants 2% task XP. The celestial build starts at the
Adventurer Core and branches into Discipline, Health, Intelligence, Finance,
Social, and rare Destiny talents.

Multiple characters can coexist in one local roster. Each character keeps an
independent avatar, build, XP ledger, currency, rewards, titles, medals, and daily
quest claims. Newly completed tasks are awarded only to the character that is
active when the completion is first processed; a global processed-task registry
prevents switching characters from duplicating that XP. Existing single-character
profiles migrate automatically into the roster.

Progression uses a quadratic level curve: level 2 starts at 100 XP, level 3 at
400 XP, level 4 at 900 XP, and so on. Consequently, each new level takes more
XP than the previous one. The active character can also record explicit
penalties in the **Penalty Dungeon**, which deduct XP and coins without deleting
the underlying task history.

The profile includes class-specific symbols and bonuses, an equipment inventory,
level-up loot, a skill tree, a growing pet, streak tracking, and worlds unlocked
by level. Ordinary level rewards favor common gear; rare, epic, and legendary
items have deliberately low drop rates. The weekly boss is based on the XP
earned during the current calendar week and grants a guaranteed rare-or-better
drop only once per character and week.

The **Life Project** section turns a long-term objective into a campaign. Its
ordered chapters can be linked to projects, so each chapter's progress is the
completion percentage of that project's tasks. This keeps daily work connected
to the campaign while allowing a final chapter to represent the final boss.
